# R2.0A-4A — Strategic Decision Audit approved-Research-Evidence consumer

Chain: R2.0A-1 -> R2.0A-2 -> R2.0A-3 -> R2.0A-4A.

This wave adds ONE bounded production consumer. It lets a canonical
`strategic_audit` project consume currently-authorized Research Evidence during
the `audit` and `strategy` phases only, while preserving every A-2/A-3
guarantee. It does not begin a general A-4 program.

## Ownership boundary

- **A-2 owns membership.** Which claims/sources/evidence/relationships are
  authorized is decided by the R2.0A-1/R2.0A-2 usage-authorization contract.
- **A-3 owns presentation disclosure.** Which fields are visible for a scope is
  decided by the frozen `research_evidence_presentation_disclosure` policy.
- **A-4A owns consumption only.** It calls the public A-3 entry
  `project_research_evidence_presentation(conn, project_id=..., usage_scope=internal_analysis)`
  with `internal_analysis` fixed mechanically, then reshapes the already-
  disclosed projection into a deterministic, bounded, model-facing prompt block
  and records a bounded consumption attestation.

A-4A never creates authorization, never re-evaluates A-2 eligibility, never
accepts a caller-selected `usage_scope`, never calls A-2 authorization or
repository internals, and has no code path that can resurrect revoked, stale,
ineligible, candidate, or unauthorized evidence — such items are absent from the
projection by construction.

## Production surface

- NEW: `mas/research_evidence_context.py` — the consumer/renderer, the read-only
  async->sync bridge, the consumption attestation, and the Decision Trace impact
  projection.
- MODIFIED: `mas/orchestrator.py` — `run_phase_node` loads/gates/bounds Research
  Evidence for audit/strategy and injects it via explicit byte-stable
  `research_evidence_section` parameters on `build_audit_prompt` /
  `build_strategy_prompt`.
- MODIFIED: `mas/explainability.py` — `PhaseTraceSummary.research_evidence_impact`
  mirrors the retrieval-impact pattern.

Migration v62 remains unused. No new migration is added by this wave.

## Gating

Consumption runs only when the phase is `audit` or `strategy` AND the canonical
normalized project type is `strategic_audit` (legacy/default `None`/``/`default`/
`strategic` all normalize to `strategic_audit`). `ai_readiness`,
`automation_roi`, and `technology_readiness` never consume, even though the first
two share the strategic-audit phase sequence. `classify`, `hypotheses`,
`gauntlet`, `sqi`, `monitor`, and `report` never consume.

## Consumer rendering contract

The renderer is a CONSUMER-INPUT ALLOWLIST, not a new authorization policy. It
admits only reasoning-useful fields and emits retained values verbatim — no
narrative synthesis, paraphrasing, summarization, invented conclusions, or new
probabilities. It preserves provenance, epistemic status, confidence,
limitations, `does_not_prove`, `semantic_relationship`, and citations. It omits
raw persistence/ledger mechanics (revision ids, sequences, blob/metadata ids,
authorization/review/intake ids, storage keys, raw capture locators).

The block is a single clearly labeled `AUTHORIZED RESEARCH EVIDENCE (INTERNAL
ANALYSIS)` section, separate from `RETRIEVAL-APPROVED KNOWLEDGE`. The two systems
are never merged and never de-duplicated against each other; contradictory items
may coexist, each with its own provenance. An injection-safety preamble marks the
content as untrusted evidence, never instructions.

## Boundedness

The complete model-facing block has a frozen budget of 65536 UTF-8 bytes. A block
whose full rendering would exceed the budget is never injected: the phase is
blocked with reason `research_evidence_prompt_overflow`. There is no partial or
"first N" block, and no partial evidence prompt reaches the model. A-2/A-3 caps
are unchanged.

## Fail-closed matrix

When the feature is enabled and consumption applies:

- DB / authoritative connection unavailable -> block, reason
  `research_evidence_unavailable`.
- Malformed/corrupt A-2 or A-3 state / integrity failure -> block, reason
  `research_evidence_integrity_error`.
- A-2 capacity overflow -> block, reason `research_evidence_capacity_overflow`.
- Consumer 65536-byte overflow -> block, reason
  `research_evidence_prompt_overflow`.

Blocking a phase fails it before any LLM call and exposes a bounded, non-secret
operator diagnostic (no SQL, paths, or credentials). A valid typed empty
projection is not a failure: the phase proceeds and a bounded "checked and empty"
attestation is recorded. With the feature off (or a non-consuming phase/project)
there is no database access, no attestation event, and legacy prompts stay
byte-identical.

## Read-only posture

The consumer opens its own authoritative PostgreSQL connection through an
injectable seam, enforces `autocommit = False` and `read_only = True`, calls the
public A-3 entry, never commits, and closes safely. It takes no transaction
ownership of A-2/A-3 data and mutates nothing. Blocking psycopg I/O runs off the
event loop via `asyncio.to_thread`.

## Provenance / attestation

Consumption reuses `state.policy_audit_log` via `log_policy_event` with the
stable event type `research_evidence_consumption`. Each event carries
`project`/phase, `usage_scope=internal_analysis`, status (`used`/`empty`/
`blocked`), the projection fingerprint, the presentation policy identity
(identifier/version/fingerprint), claim/source/evidence/relationship counts,
bounded source identities (snapshot id + citation label), and the blocked reason
when applicable. The Decision Trace exposes this as a parallel Research Evidence
impact projection on each audit/strategy phase trace, served by the existing
trace route. This is consumption attestation and fingerprint traceability, not a
perfect historical replay; a future bounded wave may add stronger persisted
consumption records if real usage requires them.

## Out of scope for this wave

Staleness/re-entry automation, report/export/client-report consumption, scenario
consumption, Automation ROI / AI Readiness / Technology Readiness consumers, the
full A-4 matrix, cross-decision/cross-project learning, and migration v62.
`internal_analysis` Research Evidence must not automatically flow into the report
phase; any effect on final reports occurs only indirectly through normal stored
audit/strategy outputs.
