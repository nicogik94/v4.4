# v4.6 Incident Runbook — Parent Rows and Decision Event Persistence

## 1) Root Cause Summary
- `store.save()` persisted `state_snapshots` but did not always ensure a matching parent row in `projects`, causing FK failures in child tables (`outcomes`, `decision_events`, `approvals`, `policy_decisions`).
- Decision event writes previously bound timestamp strings to `timestamptz` parameters instead of `datetime` objects, causing asyncpg binding failures and fail-soft fallback to memory.

## 2) What Changed
- `mas/store.py`
  - `save()` now upserts `projects` before writing `state_snapshots`.
  - `created_at` is bound as a `datetime` object for `timestamptz`.
  - `delete()` removes parent row in `projects` after snapshot delete.
- `mas/decision_events.py`
  - `append()`, `record_approval()`, and `record_policy_decision()` bind Python `datetime` objects for `timestamptz` writes.
- Added backfills:
  - `mas/sql/v46_backfill_projects_from_state_snapshots.sql`
  - `mas/sql/v46_backfill_decision_events_from_durable_tables.sql`

## 6) Rollback Notes
- Code rollback: revert `mas/store.py` and `mas/decision_events.py` to the previous commit.
- Data backfills are additive and non-destructive; rollback means disabling future usage, not deleting inserted history.
- If needed, isolate backfill-inserted rows by `actor_type='backfill'` and `actor_id='v46_backfill'` for review.

## 7) Known Limitation
- Historical event logs cannot be perfectly reconstructed:
  - hash-chain continuity (`prev_event_id`, `event_hash`) for missed historical events is not recoverable with full fidelity.
  - only minimal durable-table-backed events are backfilled.
- Diagnostic query for projects likely affected by historical event gaps:

```sql
WITH outcome_rows AS (
  SELECT project_id, COUNT(*) AS outcomes_count
  FROM outcomes
  GROUP BY project_id
),
outcome_events AS (
  SELECT project_id, COUNT(*) AS outcome_events_count
  FROM decision_events
  WHERE event_type = 'outcome.recorded'
  GROUP BY project_id
),
project_created_events AS (
  SELECT project_id, COUNT(*) AS project_created_count
  FROM decision_events
  WHERE event_type = 'project.created'
  GROUP BY project_id
)
SELECT
  p.id,
  p.name,
  COALESCE(orw.outcomes_count, 0) AS outcomes_count,
  COALESCE(oe.outcome_events_count, 0) AS outcome_events_count,
  COALESCE(pce.project_created_count, 0) AS project_created_count
FROM projects p
LEFT JOIN outcome_rows orw ON orw.project_id = p.id
LEFT JOIN outcome_events oe ON oe.project_id = p.id
LEFT JOIN project_created_events pce ON pce.project_id = p.id
WHERE COALESCE(orw.outcomes_count, 0) > COALESCE(oe.outcome_events_count, 0)
   OR COALESCE(pce.project_created_count, 0) = 0
ORDER BY p.created_at DESC;
```
