# v4.4 Tranche 1 Manual QA Checklist

Use this checklist to manually accept the tranche-1 baseline.

## Preconditions

- API is running
- dashboard is reachable
- operator can create and edit projects

## 1. Create a project

- Open `dashboards/index.html`
- Confirm the API health pills are green
- Create a new project with:
  - project name
  - brief
  - supporting data
  - risk classification
- Confirm the new project appears in the queue
- Confirm the drill-in opens successfully

## 2. Run through report

- Start a full run for the new project
- Confirm phases advance without frontend confusion about current state
- Wait for the project to complete through `report`
- Confirm `report` is visible in the drill-in

## 3. Verify Workspace state

- Open the `Workspace` subtab
- Confirm `project_status` is operationally sensible
- Confirm the phase/status strip matches the project state
- Confirm the Workspace shows:
  - score summary
  - hypothesis table
  - active risks
  - evidence timeline
  - approvals/review panel
  - re-entry history
  - decision object health
- Confirm `decision_object_health.status` is `fresh`

## 4. Verify Dossier vs Workspace split

- Open the `Dossier` subtab
- Confirm it is the place where editable fields live
- Confirm `Workspace` is read-oriented and operational
- Confirm there is no ambiguity about where to edit versus where to monitor

## 5. Edit upstream dossier content

- In `Dossier`, edit an upstream input such as:
  - `brief`, or
  - `data`, or
  - an upstream structured phase output
- Save the edit
- Confirm the change persists after refresh

## 6. Verify downstream becomes stale

- Return to `Workspace`
- Confirm `project_status` becomes `stale` when expected
- Confirm downstream phases are marked stale
- Confirm stale state is visible without reading raw JSON

## 7. Rerun and verify freshness returns

- Rerun the workflow
- Confirm it resumes from the first stale or unfinished phase
- Wait for completion
- Confirm `project_status` returns to `completed`
- Confirm `decision_object_health.status` returns to `fresh`

## 8. Verify approvals

- Use an approval-relevant scenario if available
- Confirm pending approval is surfaced in Workspace as review-required state
- Confirm granting approval clears the pending review condition
- Confirm the approval panel reflects the updated state

## 9. Verify exports and audit trail

- Download both export formats currently supported by the app
- Confirm the files are generated successfully
- Open the project audit trail
- Confirm operator edits and workflow-relevant events are logged

## 10. Verify no regression in operator flow

- Confirm queue loads normally
- Confirm drill-in still opens
- Confirm `Report`, `Audit log`, `Raw state`, `Dossier`, and `Workspace` all render
- Confirm no hidden dependency on raw state is required for normal operation

## Acceptance outcome

Tranche 1 is acceptable if:

- the project can be created, completed, edited, rerun, and exported
- Workspace reflects backend-computed operational state accurately
- Dossier remains the authoritative edit surface
- stale and fresh transitions are visible and understandable
- approvals and audit trail remain intact
