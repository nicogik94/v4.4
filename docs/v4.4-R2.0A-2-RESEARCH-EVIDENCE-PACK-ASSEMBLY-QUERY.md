# R2.0A-2 — Bounded Research Evidence Pack Assembly and Query

R2.0A-2 adds one deterministic, read-only aggregate query over the canonical
Research Evidence Pack foundation introduced by R2.0A-1. The query identity is
the explicit pair `(project_id, usage_scope)`. The existing SQL-backed v51-v57
and v61 stores remain the sole sources of truth; this wave creates no parallel
pack, index, authorization lifecycle, or mutable evidence record.

## Discovered v61 contract

- Project context is the highest `context_sequence` for the project.
- A claim annotation is current only when it has the highest
  `annotation_sequence` for its project-scoped canonical claim.
- Usage scopes are independent. Absence is unauthorized.
- The latest authorization-ledger decision for an intake-item pair and scope is
  authoritative. A latest revocation has no fallback to historical approval.
- Authorization binds the exact current annotation, claim-support assessment,
  claim review, and evidence review. Any newer basis invalidates the binding.
- An effective relationship also requires eligible support dimensions, approved
  endpoint reviews, available endpoints, and current endpoint lineage.
- Project identity is enforced across every canonical join.
- Canonical ordering is claim, source snapshot, authorization sequence, and
  authorization identity, with additional canonical identifiers used only to
  make aggregate ordering and deduplication total and deterministic.
- A current pack admits at most 50 distinct source snapshots and 200 distinct
  canonical claims. R2.0A-2 additionally bounds the materialized relationship
  cross-product to 10,000 canonical claim/fact relationships and fails closed
  rather than truncating an over-capacity result.

## Aggregate contract

`assemble_research_evidence_pack(conn, *, project_id, usage_scope)` requires a
UUID project identity and an explicit `UsageScope`. It returns an immutable,
strict aggregate containing only data reached through currently effective
authorizations for that project and scope:

- the current project context, when one exists and the pack has effective
  relationships;
- current annotations embedded in the authorized canonical claims;
- authorized source snapshots and their current bound source metadata;
- authorized candidate-fact evidence and its current bound fact metadata;
- deduplicated canonical claim/evidence relationships and their exact
  authorization and claim-support basis; and
- source, claim, evidence, and relationship counts that are validated against
  the immutable collections.

The aggregate is a backend domain DTO, not an operator or client presentation
projection. It deliberately omits storage references, actors, request IDs,
free-form metadata JSON, authorization reasons, and presentation labels that
are unnecessary for bounded canonical assembly.

### Typed empty pack

A valid project with no currently effective relationships returns a typed empty pack.
The result preserves `project_id` and `usage_scope`, has `context=None`,
zero counts, and empty immutable tuples for claims, sources, evidence, and
relationships. Missing context or annotations do not themselves produce a
domain error. A stored context is not emitted when there is no authorized pack.

### Fail-closed behavior

The query rejects or fails closed for:

- an invalid or nonexistent project identity;
- an invalid or omitted usage scope;
- cross-project joins;
- malformed or internally inconsistent persisted data;
- more than 50 distinct sources, 200 distinct claims, or 10,000 canonical
  relationships;
- disabled Research Evidence functionality; and
- any relationship whose latest authorization is revoked or whose bound
  annotation, support assessment, review decision, availability, or lineage is
  no longer current and eligible.

No historical authorization is used as fallback. Duplicate intake wrappers for
the same canonical claim/fact relationship collapse deterministically to one
relationship; conflicting duplicate canonical content fails closed.

## Read-only and transaction contract

Assembly performs bounded project existence, relationship, and optional context
reads. It does not insert, update, delete, allocate sequences, acquire advisory
or explicit row/table locks, create temporary canonical state, commit, roll
back, close the connection, or otherwise take ownership of the caller's
transaction. It never silently repairs malformed state and never truncates an
over-capacity pack into apparent success.

## In scope

- deterministic bounded pack assembly;
- current/effective authorization only;
- explicit `UsageScope` query;
- typed empty-pack behavior;
- strict immutable aggregate models; and
- read-only repository and feature-gated service contracts.

## Out of scope

- API;
- UI or dashboard work;
- exports;
- operator/client presentation projections;
- automatic authorization;
- Automation ROI execution;
- scenario execution;
- consumer integration;
- semantic claim proof generation; and
- migration v62.

Migration v62 remains unused.

## Dependency order

`R2.0A-1 -> R2.0A-2 -> R2.0A-3 -> R2.0A-4`

R2.0A-3 may build explicitly authorized presentation projections over this
aggregate. R2.0A-4 may integrate approved consumers. Neither responsibility is
implemented here.
