# R2.0A-1 — Canonical Research Evidence Pack Foundation

R2.0A-1 implements the approved `REUSE_EXISTING_RESEARCH_EVIDENCE`
architecture. The existing SQL-backed research-evidence subsystem remains the
sole canonical source of truth. This wave introduces no ProjectState pack or ID
index, no source or claim store, no parallel review lifecycle, and no mutable
evidence record.

## Contract

Migration v61 adds three append-only, project-scoped ledgers: project-context
revisions, canonical-claim annotation revisions, and explicit usage
authorization decisions. Server-owned insert preparation assigns UUIDs,
monotonic scoped sequences, immediate predecessors, bound current-basis
identities, and timestamps. ALWAYS-enabled mutation guards reject updates and
deletes. Restrictive same-project foreign keys preserve canonical lineage.

Context limitations, unresolved gaps, and annotation limitations are bounded
JSON arrays containing only strings. PostgreSQL strips the frozen Python
`str.strip()` edge-whitespace set, validates length and distinctness after that
canonicalization, and stores the canonical strings while preserving case,
internal whitespace, and array order. U+FEFF is outside the frozen edge-trim set;
U+FEFF remains preserved deliberately. Required JSON collections reject SQL
NULL before canonicalization. SQL NULL, JSON null, and `[]` are distinct: SQL
NULL and JSON null are rejected, while an explicit empty array is accepted and
stored exactly as `[]`. Related-claim members must also be JSON
strings; accepted UUID spellings are stored as canonical `uuid::text`, in input
order, before validation against distinct canonical same-project claim drafts.
Claim annotations separate epistemic status, categorical confidence, and
optional explicitly sourced probability. Confidence and probability are never
derived from one another.

Complete reapply validates the structured identity of every v61 column,
constraint and backing index, including the portable default-collation contract;
the complete non-internal trigger inventory across all six relations; exact
function definitions and ownership; complete effective owner-only table and
function ACL rows; exact NULL/default column-level ACL state for every column;
the clean NULL reloptions state of every required index; and disabled,
non-forced RLS state for every required relation. Any catalog or historical
divergence fails the single migration transaction without repairing objects,
privileges, triggers, collations, index options, relation state, or historical
data.

Usage scopes are independent and absence is unauthorized. Authorization binds
the exact current annotation, claim-support assessment, and both endpoint review
decisions. A newer bound input makes that authorization fail closed; reads never
fall back to an older authorization. Revocation remains possible after later
ineligibility, and reauthorization must bind a new current basis. Review approval
and consumer-binding disposition are not authorization.

Services retain the existing `MAS_RESEARCH_EVIDENCE_ENABLED` gate. Every write
recursively detaches caller-owned models into plain Python data and reconstructs
the strict create contract, so copied nested probability models cannot bypass
finite, range, completeness, or six-decimal-place validation. Decimal values are
preserved exactly and excess precision is rejected before any savepoint or
business SQL.

The caller owns the transaction. Autocommit is unsupported, and pack writes
support PostgreSQL `READ COMMITTED` isolation only. `REPEATABLE READ`,
`SERIALIZABLE`, and any other isolation are rejected before the first request
lookup, project lock, savepoint, eligibility check, allocator mutation, or
insert. The service and directly callable authorization repository insertion
share this check. The repository never commits or performs a connection-wide
rollback; bounded nested savepoints are deterministically released on success
and failure.

Repository race recovery is allowlisted by exact diagnostic identity. The
unique-request path requires SQLSTATE `23505` together with constraint
`uq_reuad_scope_request`. The transition path requires SQLSTATE `23514`, the
complete approved transition message, and the genuine absence of competing
constraint, schema, or table identity. SQLSTATE-only, constraint-only,
message-substring, and unrelated integrity failures do not enter recovery and
retain their original exception identity.

Effective authorization listings have an explicit stable order by usage scope,
canonical claim draft, canonical evidence source snapshot, authorization
decision sequence, and authorization decision ID. Current packs are limited to
50 distinct evidence source snapshots and 200 distinct canonical claims;
immutable history is not capped.
