# Local Runtime Launch and Smoke Checks

This runbook is for local, single-operator use. It does not make the API public-safe and does not add authentication, tenancy, rate limits, or deployment hardening.

For `POST /projects` payload shapes, `X-Request-ID` correlation, and run ID behavior, see `docs/v5-INGESTION-CONTRACT.md`.

## Standard Launch

From PowerShell:

```powershell
cd "C:\dev\v4.4\mas"
.\scripts\local_runtime_check.ps1
```

To rebuild the app image before launch:

```powershell
.\scripts\local_runtime_check.ps1 -RebuildApp -TimeoutSeconds 180
```

The script:

- verifies the Docker CLI is installed
- verifies the Docker daemon is reachable
- starts `db`, `redis`, and `app` with Docker Compose unless `-SkipComposeUp` is set
- detects the published app port with `docker compose port app 8000`
- falls back to `http://localhost:8001` if Docker does not report a port
- checks `/health`, `/runtime/preflight`, and `/runtime/release-readiness`

The dashboard remains:

```text
dashboards/index.html
```

The compose file currently publishes the app as `8001:8000`. If Docker reports a different host port, the script uses Docker's reported port. You can override detection:

```powershell
.\scripts\local_runtime_check.ps1 -ApiBase "http://localhost:8001"
```

## Manual Fallback

If you need to run the checks manually:

```powershell
cd "C:\dev\v4.4\mas"
docker compose up -d
curl.exe http://localhost:8001/health
curl.exe http://localhost:8001/runtime/preflight
curl.exe http://localhost:8001/runtime/release-readiness
```

If port `8001` does not work, ask Docker for the actual app port:

```powershell
docker compose port app 8000
```

Use the reported host port in the curl URLs.

## Recovery

### Docker daemon not running

Start Docker Desktop, wait until it reports that Docker is running, then retry:

```powershell
.\scripts\local_runtime_check.ps1
```

### WSL mount failures

Common messages include:

- `error while creating mount source path`
- `mkdir /run/desktop/mnt/host/c: file exists`
- `unable to get image ... dockerDesktopLinuxEngine`

Recovery:

```powershell
cd "C:\dev\v4.4\mas"
docker compose down --remove-orphans
wsl --shutdown
```

Then quit Docker Desktop, reopen Docker Desktop, wait until Docker is running, and retry the script.

### App container not healthy

Check service state and recent logs:

```powershell
docker compose ps
docker compose logs --tail=120 app
```

Then rerun:

```powershell
.\scripts\local_runtime_check.ps1 -TimeoutSeconds 180
```

### Port mismatch

Use Docker's published port:

```powershell
$port = (docker compose port app 8000).Split(":")[-1]
curl.exe "http://localhost:$port/health"
```

Or pass the known URL:

```powershell
.\scripts\local_runtime_check.ps1 -ApiBase "http://localhost:8001"
```

## Smoke Export Scan

1. Open `dashboards/index.html`.
2. Create and run a smoke project.
3. Export these six artifacts:
   - report PDF
   - client dossier PDF
   - operator dossier PDF
   - machine archive ZIP
   - client monitoring XLSX
   - operator monitoring XLSX
4. Copy the downloads into one smoke directory.
5. Run:

```powershell
cd "C:\dev\v4.4\mas"
python scripts/scan_smoke_exports.py "<path-to-smoke-directory>"
```

For machine-readable output:

```powershell
python scripts/scan_smoke_exports.py "<path-to-smoke-directory>" --json
```

For stricter filename matching:

```powershell
python scripts/scan_smoke_exports.py "<path-to-smoke-directory>" --project-id "<project-id>"
```

The scanner expects filenames generated by the export API, such as:

```text
<project-id>-report-YYYYMMDDTHHMMSSZ.pdf
<project-id>-client_dossier-YYYYMMDDTHHMMSSZ.pdf
<project-id>-operator_dossier-YYYYMMDDTHHMMSSZ.pdf
<project-id>-machine_archive-YYYYMMDDTHHMMSSZ.zip
<project-id>-client_monitoring_template-YYYYMMDDTHHMMSSZ.xlsx
<project-id>-operator_monitoring_template-YYYYMMDDTHHMMSSZ.xlsx
```

## Git Hygiene

Do not commit local runtime or smoke artifacts:

- `docker-compose.yml` unless the change is intentional and reviewed
- `upload_store/`
- `__pycache__/`
- `*.sqlite3`
- `exports/`
- downloaded PDF, ZIP, XLSX, DOCX smoke files
- temporary scan or debug scripts

Before committing runtime-check changes, restore tracked generated artifacts if they are dirty:

```powershell
git restore scenario_shadow.sqlite3 scenarios/__pycache__/__init__.cpython-312.pyc tools/__pycache__/scoring.cpython-312.pyc
```
