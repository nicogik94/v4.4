# File Cleanup Proposal — v4.4

The Decision Engine bundle has 85 files. About 60 are working code or daily-use docs. The other 25 are historical artifacts, pitch material, or alternate integration targets that were useful when they were created but now create the "which files are important?" confusion you flagged.

**This document does not move or delete anything.** It proposes three categories. You decide what to do.

---

These are the files you actually open during normal operation. Everything else exists to support these.

- `README.md` ← repo map and changelog summary

**Recommendation:** keep all of these prominent. No changes.

## Category 3 — Archive candidates (~25 files)

These are real artifacts from the engine's history. They were valuable when created. They are no longer in the daily flow and could move to an `archive/` subdirectory without breaking anything functional. The proposal: move them, do not delete them.

### Historical audit reports (5 files)

These document the v4.0 → v4.1 evolution. Useful for "how did we get here" questions, irrelevant for day-to-day use.

- `docs/v4-ARVV-Audit-Report.md` ← the original audit that triggered v4.1
- `docs/v4-ARVV-MasterPlan-Audit.md` ← the audit of the master plan
- `docs/v4-Comprehensive-Analysis-Report.md` ← the document the audit was based on
- `docs/v4.1-ARVV-v5-Plan-Audit.md` ← the v5 plan self-audit
- `JOB_A_COMPLETION.md` ← v4.0 → v4.1 audit reconciliation note

**Proposal:** move to `archive/audits/`.

### Legacy engine documentation (3 files)

These were the engine's original documentation; their content is now in the prompt files and `mas/README.md`. Keeping them adds confusion because they describe an older shape.

- `docs/v4-Multi-Agent-System-Prompt.md` ← 930-line monolith, already flagged for retirement in v5 plan
- `docs/v4-MAS-Blueprint.docx` ← legacy blueprint, content moved to mas/README and prompts/
- `docs/v4-Strategy-Quality-Research.docx` ← research notes

**Proposal:** move to `archive/legacy-docs/`. Cross-references in other docs point to current versions.

### Pitch and launch material (6 files)

These are sales/marketing artifacts for the consulting practice that pitches the Decision Engine to clients. They are not the engine itself. Keeping them in the same directory tree as the engine confuses "I want to use the tool" with "I want to sell the tool."

- `deck/v4-AI-Decision-Engine-Opportunity.pptx` ← sales deck
- `launch/v4-90Day-MasterPlan-CORRECTED.docx` ← practice launch plan
- `launch/v4-90Day-MasterPlan-Interactive.html` ← interactive version of the same
- `frontend/v4-pitch.jsx` ← marketing landing page (React)
- `lead-magnets/roi-calculator.html` ← pitch tool
- `lead-magnets/sample-decision-audit.md` ← sample dossier for prospects

**Proposal:** move to a separate `pitch/` directory at the same level as `mas/`. Or, even better, move to a different repository entirely — the sales materials and the engine have different audiences and different update cadences.

### Alternate integration targets (10 files)

These are configurations that let the engine run via Claude Projects or Custom GPTs instead of via the FastAPI stack. They were useful when the FastAPI stack didn't exist. They are now duplicative: every operation possible via these files is also possible via the API and the console.

- `mas/gpt_instructions/00-orchestrator.md`
- `mas/gpt_instructions/01-classify-agent.md`
- `mas/gpt_instructions/02-hypotheses-agent.md`
- `mas/gpt_instructions/03-gauntlet-agent.md`
- `mas/gpt_instructions/04-audit-agent.md`
- `mas/gpt_instructions/05-strategy-agent.md`
- `mas/gpt_instructions/06-sqi-agent.md`
- `mas/gpt_instructions/07-monitor-agent.md`
- `mas/gpt_instructions/08-report-agent.md`

**Proposal:** move to `archive/gpt-builder-integration/` with a one-line note that this was an alternate integration target retired when the v4.4 console shipped. **Caveat:** if you ever want to demo the engine to someone who doesn't want to install Docker, the GPT Builder version is a useful fallback. Don't delete; archive.

### Superseded operator interfaces (2 files)

- `frontend/v4-workflow-app.jsx` ← the OLD React-based workflow UI, fully replaced by `dashboards/index.html` in v4.2 and improved in v4.4. Kept around because the v4.2 release was non-destructive.
- `excel/v4-MAS-Command-Center.xlsx`, `excel/v4-Command-Center.xlsx`, `excel/v4-Meta-Learner-Database.xlsx` ← the Excel-based command center, partially superseded by the dashboard's System tab. Still useful if you want to do ad-hoc analysis on calibration data outside the engine.

**Proposal:** move `frontend/v4-workflow-app.jsx` to `archive/`. **Keep the Excel files** — they are an offline analysis surface the dashboard does not replace.

---

## What this proposal does NOT do

- **Does not delete anything.** Archive ≠ delete. Everything stays in the repository, just in `archive/`.
- **Does not change cross-references.** I'd verify that no doc references the archived files before executing the move. If a reference exists, the archive plan needs adjustment.
- **Does not touch the running engine.** All `mas/*` files stay where they are.
- **Does not move v4.4 documentation** (`START_HERE.md`, `compliance/`, `docs/security/`, `docs/v4.3-MATURITY-SELF-ASSESSMENT.md`, `docs/v5-ROADMAP.md`).
