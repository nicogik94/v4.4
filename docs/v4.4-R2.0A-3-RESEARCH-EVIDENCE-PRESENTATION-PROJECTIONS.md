# R2.0A-3 — Explicitly Authorized Presentation Projections

R2.0A-3 adds one deterministic, read-only, omission-only presentation
projection over the R2.0A-2 Research Evidence Pack aggregate. The projection
identity is the pack identity: the explicit pair `(project_id, usage_scope)`.
This wave creates no migration, no SQL, no persisted projection state, no new
authorization primitive, and no consumer integration.

## Ownership boundary

- **R2.0A-2 owns membership.** Which claims, sources, evidence, and
  relationships are currently authorized for a project and scope is decided
  exclusively by the v61 usage-authorization ledger through
  `assemble_research_evidence_pack`. R2.0A-3 never re-evaluates eligibility,
  currency, retention, review, or capacity.
- **R2.0A-3 owns presentation disclosure.** A frozen, versioned presentation
  disclosure policy fixes which fields of already-authorized pack content are
  presentation-safe for each canonical `UsageScope`, and a pure function
  reshapes the pack into an immutable typed projection.
- **R2.0A-4 owns consumption.** Rendering and consumer integration are out of
  scope here.

**A-3 does not create evidence authorization.** Changing the in-code
disclosure policy never authorizes or de-authorizes evidence; it only changes
the presentation-safe shape of content that the v61 ledger already authorized
for the scope.

## UsageScope reuse

The canonical `UsageScope` (`internal_analysis`, `operator_dossier`,
`client_report`) is the complete presentation-context vocabulary. No parallel
audience enum exists. The pure projection derives its disclosure tier from
`pack.usage_scope`; presentation context is never a separate caller-supplied
input, so caller-controlled audience escalation is structurally impossible.

## Frozen disclosure inventory

Policy `research_evidence_presentation_disclosure` version `1.0.0` uses
**DEFAULT DENY** semantics: a field that is not explicitly allowed for a scope
must be `None` in that scope's projection, and the projection model enforces
this mechanically for every field of every projected member. A model field
unknown to the policy can never silently appear.

Per-member allowlists (`allow`; `require` marks fields that must accompany the
member wherever it is projected):

- **context** — all scopes: `research_question`, `project_limitations`,
  `unresolved_gaps` (all required). internal/operator add `recorded_at`.
  internal adds `context_revision_id`, `context_sequence`.
- **claim** — all scopes require `claim_draft_id`, `claim_text`,
  `claim_category`, `epistemic_status`, `confidence_label`,
  `supports_statement`, `does_not_prove`, `limitations`; all scopes allow the
  optional `explicit_probability`. internal/operator add `decision_relevance`,
  `related_claim_draft_ids`, `annotation_recorded_at`. internal adds
  `annotation_revision_id`, `annotation_sequence`.
- **probability** — all scopes require `value`, `provided_by`.
  internal/operator add `provenance_reference`, `provenance_note`.
- **source** — all scopes require `source_snapshot_id`,
  `canonical_source_locator`, `publisher`, `author`, `citation_label`,
  `declared_quality_tier` and allow `published_at`, `retrieved_at`.
  internal/operator add `source_kind`, `captured_at`,
  `declared_quality_rationale`. internal adds the raw `source_locator`,
  `source_blob_id`, `source_metadata_revision_id`.
- **evidence** — all scopes require `candidate_fact_revision_id`,
  `source_snapshot_id`, `fact_type`, `unit`, `citation_locator` and allow the
  complete typed fact payload (`numeric_value`, `text_value`,
  `currency_code`, `as_of_date`, `numerator_context`, `denominator_context`,
  `percentage_basis`, `percentage_subtype`, `time_unit`, `counted_entity`).
  internal adds `fact_metadata_revision_id`, `stable_fact_key`,
  `source_char_range`.
- **relationship** — all scopes require `claim_draft_id`,
  `candidate_fact_revision_id`, `source_snapshot_id`,
  `semantic_relationship`. internal/operator add `authorized_at`. internal
  adds the ledger basis (`usage_scope`, `authorization_sequence`,
  `authorization_decision_id`, `claim_intake_item_id`,
  `evidence_intake_item_id`, `claim_support_assessment_id`,
  `claim_annotation_revision_id`, `claim_review_decision_id`,
  `evidence_review_decision_id`, `locator_resolution`, `evidence_linkage`).

`operator_dossier` is deliberately not raw full fidelity: intake wrapper
identifiers, review-decision identifiers, authorization-ledger identifiers,
sequence numbers, storage identifiers, metadata-root identifiers, extraction
machinery (`stable_fact_key`, `source_char_range`), and the raw
`source_locator` are omitted. `client_report` additionally omits operator
prose (`decision_relevance`, `declared_quality_rationale`, probability
provenance), capture mechanics (`source_kind`, `captured_at`), annotation and
authorization timestamps, and `related_claim_draft_ids`. Curated citation
fields (`citation_label`, `canonical_source_locator`, `citation_locator`,
publisher/author/published/retrieved) are the client-facing provenance.

## Omission-only rule

The projection retains explicitly allowed fields verbatim and omits everything
else as `None`. It never rewrites, summarizes, shortens, paraphrases,
translates, normalizes, or replaces text, never fabricates redacted
placeholder values, and never computes derived values. Canonical retention
redaction remains the v47 retention-event mechanism, which R2.0A-2 already
honors by excluding affected members before projection.

## No member filtering

Membership in equals membership out. The projected claim, source, evidence,
and relationship identity tuples must equal the pack's exactly; the builder
fails closed on any divergence, and the projection model additionally rejects
orphans, absent relationship targets, non-canonical source bindings, and
counts that do not match the immutable collections. Bidirectional
reachability between members and relationships is required in every scope.
A-3 is not a second evidence eligibility or authorization system: it never
drops a member, never adds a member, and never resurrects anything the pack
excluded.

## Non-overclaim mechanical guarantees

- **Subset/identity:** no members beyond the authorized pack.
- **Verbatim:** every retained value equals its authorized pack value.
- **Qualifiers:** `epistemic_status`, `confidence_label`, `supports_statement`,
  `does_not_prove`, and `limitations` are required in every scope whenever
  their claim is projected, as is `semantic_relationship`
  (narrowed to authorized `support`/`qualification`) on every relationship,
  and the pack-level `project_limitations`/`unresolved_gaps` whenever context
  is projected.
- **Provenance:** every projected member keeps its canonical identity
  (`claim_draft_id`, `source_snapshot_id`, `candidate_fact_revision_id`) in
  every scope, so presentation content stays traceable to the authorized pack
  without consumers needing internal ledger mechanics.
- **No synthesis:** no narrative, conclusions, probabilities, statistics,
  scores, or calculations are generated.

A-3 cannot prevent downstream narrative overclaiming; that remains an R2.0A-4
consumer/rendering certification concern.

## Fingerprint canonicalization contract

`PRESENTATION_POLICY_FINGERPRINT` is the SHA-256 hex digest of the UTF-8
encoding of `PRESENTATION_POLICY_CANONICAL_JSON`, which is
`json.dumps(PRESENTATION_POLICY_PARAMETERS, ensure_ascii=False,
separators=(",", ":"), sort_keys=True)`.

`projection_fingerprint` is the SHA-256 hex digest of the UTF-8 encoding of
the canonical projection descriptor produced by
`canonical_presentation_projection_descriptor`. The descriptor is compact JSON
(`ensure_ascii=False`, separators `(",", ":")`, sorted mapping keys) binding:

- descriptor version `research-evidence-presentation-projection-v1`;
- policy identifier `research_evidence_presentation_disclosure`;
- policy version `1.0.0`;
- the policy fingerprint; and
- the complete projected content: `project_id`, `usage_scope`, context,
  claims, sources, evidence, relationships, and counts.

Value canonicalization: strings verbatim; UUIDs as canonical lowercase UUID
strings; booleans and integers native; `Decimal` as its exact
scale-preserving `str()` form; timezone-aware datetimes normalized to UTC via
`astimezone(UTC).isoformat()`; dates as ISO-8601 `isoformat()`; enums as
their values; nested models as mappings over their sorted field names with
omitted fields serialized as JSON null (binding the omission state);
collections as arrays in canonical member order. Floats, naive datetimes, and
unknown types are rejected. The descriptor contains no runtime timestamps, so
repeated projection of identical input under the identical policy yields an
equal object and an identical fingerprint, and any content, scope, or policy
change yields a different fingerprint. The projection model recomputes the
fingerprint during validation and rejects any mismatch.

## Empty projection

A valid typed empty pack projects to a valid typed empty projection: same
`project_id` and `usage_scope`, pinned policy identifier/version/fingerprint,
`context=None`, empty immutable member tuples, zero counts, and a valid
deterministic projection fingerprint. The service returns the projection, not
`None`.

## Errors

`project_research_evidence_presentation` preserves R2.0A-2 behavior
unchanged: pydantic `ValidationError` for invalid identity or scope,
`ResearchEvidencePackParentNotFound` for a missing project,
`ResearchEvidencePackIntegrityError` for malformed persisted state, and
`ResearchEvidencePackLimitError` for capacity overflow (capacity bounds are
inherited from A-2; A-3 adds no caps and never truncates). A-3 raises
`ResearchEvidencePresentationProjectionDisabled` when the feature gate is off
and `ResearchEvidencePresentationProjectionIntegrityError` (with exception
chaining) if projected content ever violates the projection contract. The
base class is `ResearchEvidencePresentationProjectionError`.

## Read-only contract

Projection is a pure function with no database access, no global mutable
state, and no external calls. The service entry point performs no writes,
takes no locks, opens no savepoints, never commits or rolls back, never
changes isolation, and never takes ownership of the caller's transaction; its
only reads happen inside the unchanged R2.0A-2 assembly.

## Feature gate

The existing `MAS_RESEARCH_EVIDENCE_ENABLED` gate governs the service entry
point, consistent with every other research-evidence service. No new
configuration is introduced.

## In scope

- frozen, versioned presentation disclosure policy with DEFAULT DENY;
- strict immutable projection models with fail-closed validation;
- pure deterministic projection function;
- feature-gated read-only service entry point; and
- policy and projection fingerprinting.

## Out of scope (deferred to R2.0A-4 or later)

- API;
- UI or dashboard work;
- exports;
- report generation and rendering;
- client delivery integration;
- workspace integration;
- Automation ROI consumption;
- scenario consumption;
- Strategic Decision Audit consumption;
- AI Readiness consumption;
- automatic execution;
- consumer input binding activation;
- persisted projection or delivery attestation state; and
- migration v62.

Migration v62 remains unused.
