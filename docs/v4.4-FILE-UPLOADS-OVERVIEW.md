# v4.4 File Uploads + Overview

This tranche adds two operator-facing capabilities:

1. **Bounded file uploads** for context and data
2. **Overview** as the summary-first read surface

The implementation is additive. `ProjectState` remains canonical, raw file blobs stay out of state, and uploads do **not** auto-rerun or auto-invalidate the workflow.

## Supported uploads

- `PDF`
- `DOCX`
- `TXT`
- `MD`
- `CSV`
- `XLSX`

Rules:

- uploaded binaries are stored in a local sidecar file store
- `ProjectState` stores only file manifests plus parsed additive artifacts
- document files become bounded knowledge items
- table files become bounded table knowledge items by default
- `CSV` and `XLSX` can optionally run the existing structured evidence/signal import path

## Safety contract

- no OCR
- no images
- no archives
- no macros
- no embedded execution
- unsupported MIME/extension pairs are rejected
- uploaded text is treated as untrusted source material
- raw file payloads are not persisted in canonical project state

## Important operator behavior

Uploads are visible immediately in:

- `Overview`
- `Workspace`
- `Knowledge` status
- retrieval eligibility and visibility surfaces

Uploads do **not** automatically change prior phase outputs.

If a file causes:

- new imported evidence/signals
- new retrieval-eligible knowledge

you still need a **manual rerun** before downstream analysis, strategy, or report outputs can reflect it.

## Routes

- `GET /projects/{id}/overview`
- `GET /projects/{id}/files`
- `POST /projects/{id}/files`
- `GET /projects/{id}/files/{file_id}`
- `DELETE /projects/{id}/files/{file_id}`

`POST /projects/{id}/files` uses multipart form upload.

Useful form fields:

- `file`
- `actor`
- `role`: `context | data`
- `import_mode`: `knowledge | structured_import`
- `sheet_name`: optional for `XLSX`
- `mapping_json`: optional JSON array for structured `CSV/XLSX` evidence/signal import

## Overview surface

`Overview` is the default drill-in read tab. It organizes the existing engine outputs into:

- current recommendation
- why it recommends this
- hypotheses
- strategy
- key metrics
- open questions
- sources and files
- next operator action

`Overview` is for reading.

- **Dossier** remains the edit surface
- **Workspace** remains the operational surface
- **Trace** remains the explainability surface

## Storage model

- raw binary: sidecar file store only
- persisted in state:
  - file manifest
  - source entry
  - parsed knowledge items
  - structured import artifacts if the operator chose structured import

Deleting a file removes:

- the sidecar blob
- the file manifest
- its source entry
- its additive knowledge items
- any structured imported evidence/signals tied to that upload

Deleting a file still does **not** auto-rerun the workflow.
